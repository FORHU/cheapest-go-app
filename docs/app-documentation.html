1   Product Overview

CheapestGo is a full-stack travel booking platform that enables users to search, compare, and book flights and hotels from multiple suppliers through a single, unified interface. The platform aggregates inventory from industry APIs (Duffel, Mystifly, TravelgateX) and presents them with consistent pricing, cancellation policies, and booking flows.

✈️
Multi-Provider Flight Search
Parallel search across Duffel Airways and Mystifly with normalized fare data, seat selection, and baggage add-ons.
🏨
Global Hotel Inventory
TravelgateX OTV powers hotel search with real-time availability, dynamic pricing, and free-cancellation filtering.
🗺️
Interactive Map Search
Mapbox GL map with property clustering, nearby POIs via Google Places, and side-panel comparison.
💳
Unified Checkout (Stripe)
Stripe Embedded Checkout with manual-capture for Mystifly and automatic-capture for Duffel bookings.
🤖
AI-Powered Search
Natural language search bar and AI itinerary generator for destination discovery and trip planning.
🌍
Multi-Currency Support
Real-time exchange rates with client-side conversion. Currency preference persisted per user.

State Management Strategy

The app uses a layered state approach:

  • Zustand stores — ephemeral UI state (auth, search params, booking flow, checkout)
  • TanStack Query — server cache for bookings list, trip details, profile data
  • PostgreSQL — source of truth for all business data
  • Lucia sessions — auth state, refreshed per-request in middleware

Provider Aggregation Pattern

Flight search runs Duffel + Mystifly in parallel using Promise.allSettled() with a 12-second timeout per provider. Results are normalized to a shared FlightOffer type before being cached and returned to the client. One provider failing does not block the response from the other.

// src/lib/server/flights/search-flights.ts (simplified) const [duffelResult, mystiflyResult] = await Promise.allSettled([ searchDuffel(params, { timeout: 12_000 }), searchMystifly(params, { timeout: 12_000 }), ]); const offers = [ ...(duffelResult.status === 'fulfilled' ? duffelResult.value : []), ...(mystiflyResult.status === 'fulfilled' ? mystiflyResult.value : []), ].map(normalizeToFlightOffer);

Mystifly Ticketing Loop

After a Mystifly booking is placed, the PNR may take minutes to confirm. The poll-pending-tickets cron job (every 5 minutes) checks pending PNRs via GetTicketStatus. On failure, Stripe is automatically refunded and the booking is marked failed.

6   Hotel Module

Provider: TravelgateX OTV

All hotel inventory is sourced from TravelgateX OTV via GraphQL. The integration follows a four-step lifecycle:

  1. Search — HotelX_Search query with occupancy, dates, destination
  2. Quote — HotelX_Quote to lock the rate and receive a quote token
  3. Book — HotelX_Book using the quote token with guest details
  4. Cancel — HotelX_Cancel using the booking reference
Quote Token Lifecycle A quote token is short-lived (typically 10–15 minutes). The front end starts a countdown timer once a quote is obtained. Expiry requires the user to re-search.

Hotel Search Features

  • Multi-currency pricing (base currency normalized, client-side conversion)
  • Free-cancellation badge from policy data
  • Interactive Mapbox map with property clustering
  • Nearby POIs overlay (restaurants, attractions) via Google Places
  • Voucher / discount code validation at checkout
  • Prebook price lock before final payment

7   Authentication & Sessions

Overview

Authentication is handled by Lucia v3 with a custom PostgreSQL adapter. There is no Supabase Auth dependency — all user and session data lives in the application's own Postgres database.

Password Hashing Passwords are hashed with argon2id via @node-rs/argon2 (native binding). Salt and parameters are stored as part of the hash string.

Session Cookie

Cookie name: cg-session. Flags: HttpOnly, Secure (in production), SameSite=Lax. Session tokens are long random strings stored in the sessions table.

Auth Flow

  1. User submits email/password → POST /api/auth/register or /api/auth/login
  2. Server verifies credentials, creates sessions row
  3. Session cookie set on response
  4. Next.js middleware validates/refreshes cookie on every request
  5. useAuthStore syncs user object to client state

Password Reset Flow

  1. User requests reset → POST /api/auth/forgot-password
  2. Secure token generated, stored in password_reset_tokens
  3. Reset link emailed via Resend
  4. User submits new password → POST /api/auth/reset-password?token=…
  5. Token validated (expiry + single-use), password updated, session created

8   Payments (Stripe)

Integration Model

Payments use Stripe Embedded Checkout rendered in an iframe. Two capture modes are used depending on the flight provider:

ProviderCapture ModeReason
Duffel Airways Automatic Duffel confirms booking synchronously; immediate charge is safe
Mystifly Manual PNR confirmation is asynchronous; card held until ticket is confirmed
Hotels (TravelgateX) Automatic Booking confirmed synchronously via prebook → book flow

Checkout Flow

  1. User reviews order → POST /api/flights/book or /api/booking/prebook
  2. Server creates Stripe PaymentIntent (manual or auto capture)
  3. Client renders <StripeEmbeddedCheckout /> with client secret
  4. User completes payment in Stripe iframe
  5. Stripe webhook → POST /api/webhooks/stripe triggers booking creation
  6. Booking record written, confirmation email sent via Resend

Idempotency & Double-Booking Prevention

An in-memory Set of active booking session IDs prevents concurrent requests for the same session from creating duplicate bookings. Stripe idempotency keys are also passed to prevent duplicate PaymentIntents.

Future Enhancement The in-memory session lock does not survive across container restarts or multiple instances. Migrating to Redis-backed locking is planned for multi-instance production scaling.

9   Database Schema

There is no ORM in this project — no Prisma schema exists. The schema below is transcribed directly from the raw SQL migration files managed by dbmate in db/migrations/ (20260601000001_schema.sql, …_auth.sql, and five follow-up patch migrations). The connection uses postgres.js with a shared pool. Development runs Postgres 17 in Docker on port 5433; production uses AWS RDS.

Naming note Several tables carry names from an earlier Supabase-based version of the schema (e.g. profiles, weekend_flight_deals used for hotel deals, onda_properties/etg_hotel_index from earlier provider integrations). They remain in production and are documented as-is rather than renamed.

10   API Reference

Flight Endpoints

  • POST /api/flights/search Parallel search across Duffel + Mystifly. Returns normalized FlightOffer[]. Rate-limited to 20 req/min per IP.
  • POST /api/flights/book Creates a booking session and Stripe PaymentIntent. Returns client secret for Embedded Checkout.
  • POST /api/flights/confirm Fallback endpoint — checks DB for existing booking, creates if missing. Used when webhook fires before redirect.

Hotel / Booking Endpoints

  • POST /api/booking/prebook Obtains a quote token from TravelgateX and locks the hotel rate.
  • POST /api/booking/confirm Final booking with guest details using the prebook quote token.
  • GET /api/booking/[id] Retrieve full booking details for the authenticated user.
  • POST /api/booking/cancel Initiates cancellation via TravelgateX and triggers refund if applicable.

Auth Endpoints

  • POST /api/auth/register Create account with email/password. Returns session cookie.
  • POST /api/auth/login Authenticate with email/password. Returns session cookie.
  • POST /api/auth/logout Invalidates the current session and clears the cookie.
  • POST /api/auth/forgot-password Sends a password reset email with a signed token link.
  • POST /api/auth/reset-password Validates reset token and updates the user's password.
  • GET /api/auth/me Returns the current authenticated user's profile.

Utility Endpoints

  • GET /api/airports Airport search by name or IATA code for autocomplete.
  • POST /api/places Google Places autocomplete and place detail lookups.
  • POST /api/exchange-rates Returns current exchange rates (1-hour cache).
  • POST /api/webhooks/stripe Stripe event receiver — triggers booking creation on payment success.

11   Cron Jobs & Automation

Cron jobs are implemented as Next.js API routes under /api/cron/, secured by a CRON_SECRET header. An external scheduler (Coolify system cron or AWS EventBridge) calls these routes on schedule.

JobRouteSchedulePurpose
poll-pending-tickets /api/cron/poll-pending-tickets */5 * * * * Check Mystifly PNR status; auto-refund on failure
sync-flight-deals /api/cron/sync-flight-deals 0 * * * * Refresh featured flight deals cache
sync-hotel-deals /api/cron/sync-hotel-deals 0 * * * * Refresh featured hotel deals cache
refresh-popular-flights /api/cron/refresh-popular-flights */30 * * * * Pre-warm flight search cache for high-demand routes
check-price-alerts /api/cron/check-price-alerts */15 * * * * Scan user price alerts and send triggered notifications
cleanup-sessions /api/cron/cleanup-sessions 0 3 * * * Delete expired Lucia sessions from the database
Security All cron routes validate Authorization: Bearer <CRON_SECRET>. Requests missing this header receive 401 Unauthorized. The secret is set as an environment variable and never logged.

12   Maps & Geolocation

Mapbox GL Integration

The hotel search map uses Mapbox GL JS via react-map-gl. Properties are rendered as custom markers and automatically cluster when zoom < 15 using supercluster + use-supercluster.

  • Click cluster → zoom to cluster bounds
  • Click property marker → show side-panel detail or navigate to /property/[id]
  • Nearby POI layer (restaurants, attractions) via Google Places API
  • Map bounds change triggers filtered results update in side panel

Google Places Integration

POST /api/places wraps the Google Places API for:

  • Location autocomplete (hotel destination search)
  • Place details (coordinates, address, photos)
  • Nearby search (POI overlay on hotel map)

16   Error Handling & Observability

Sentry Integration

Sentry is configured in three entry points: sentry.client.config.ts, sentry.server.config.ts, and sentry.edge.config.ts — covering client exceptions, server errors, and edge middleware failures respectively.

Structured Logging

Provider-specific console logs use consistent prefixes for log filtering: [Duffel], [Mystifly], [TravelgateX], [Stripe]. API call logs are persisted in the api_logs database table for audit and debugging.

Graceful Degradation

  • Flight provider timeout → return results from the other provider, not an error
  • Cache miss → live provider call with spinner; background cache write on response
  • Quote token expiry → user shown a re-search prompt, no silent failure
  • Mystifly ticket failure → automatic Stripe refund + booking marked failed

Cron Failure Handling

Cron routes return structured JSON ({ ok: true | false, message }). Failures are captured by Sentry and can be monitored via Coolify logs or connected alerting.
